Answer: no backend of our own. GitHub Pages is static HTML, which is enough for a Contact tab and the email on the page (`hello@muudelixir.com`, plus a `mailto:` link).

A real submit-able form is also possible without hosting a server: the form POSTs to a free form service (Formspree, Web3Forms, Getform, etc.) and that service emails us. Netlify Forms works the same way if we ever host there instead of GitHub Pages. A `mailto:` form (opens the visitor’s email app) needs nothing extra, but it’s flaky — especially on phones.

Shipped: Contact tab + `hello@muudelixir.com` on the page + mailto form. We’ll switch to a form service if they ask.

Tradeoffs (free form backends, for a GitHub Pages site):
- All of them: a third party sees submissions; the form key lives in public HTML; bots will try it; inbox mail can land in spam; if we hit the cap, the form silently dies until next month (or until we pay).
- Formspree: best-known, real dashboard. Free is only ~50 submissions/month — tight if the shop takes off. Captcha/file uploads are paid.
- Web3Forms: best free fit here. 250/month, works on GitHub Pages, honeypot + hCaptcha on free. Weak dashboard (30-day storage). No file uploads. Access key is public by design; Pro adds “trusted domains” so others can’t copy the key onto another site and spam us.
- Formspark: 250 submissions total, not per month — a trial, not a forever plan. After that, ~$25 one-time for a big bundle (no monthly bill). Fine if we hate subscriptions.
- Getform: small free quota, integrations are the selling point. Overkill for “email us.”
- Netlify Forms: only if we host on Netlify. Ties the form to the host; their free tier now shares credits with deploys.
- mailto: form: zero vendor, flaky on phones, no proof the message sent. Not a real form.

For this site, volume will be tiny. If they ask for a real form: Web3Forms. Until then, Contact tab + email + mailto stays.
